== Введение

В ходе выполнения практической работы была поставлена цель — изучить методы управления периферией микроконтроллера, начиная от простых процедурных алгоритмов и заканчивая объектно-ориентированным подходом с использованием UML-диаграмм, интерфейсов и шаблонов проектирования (C++ templates).

== Этап 1. Процедурный подход

Изначально был реализован базовый код «елочка» (поочередное включение светодиодов), который затем был переделан в режим «шахматка» (включение сначала четных, затем нечетных светодиодов).

=== 1.1. Код «Елочка»

[source, cpp]
----
#include "rccregisters.hpp"   // for RCC
#include "gpioaregisters.hpp" // for GPIOA
#include "gpiocregisters.hpp" // for GPIOC

std::uint32_t SystemCoreClock = 16'000'000U;

extern "C" int __low_level_init(void)
{
  // Switch on external 16 MHz oscillator
  RCC::CR::HSION::On::Set();
  while (RCC::CR::HSIRDY::NotReady::IsSet()) { }
  // Switch system clock on external oscillator
  RCC::CFGR::SW::Hsi::Set();
  while (!RCC::CFGR::SWS::Hsi::IsSet()) { }

  RCC::APB2ENR::SYSCFGEN::Enable::Set();
  return 1;
}

void delay(int cycles)
{
  for(int i = 0; i < cycles; ++i)
  {
    asm volatile("");
  }
}

int main()
{
  RCC::AHB1ENR::GPIOAEN::Enable::Set();
  RCC::AHB1ENR::GPIOCEN::Enable::Set();
  
  GPIOA::MODER::MODER5::Output::Set();
  GPIOC::MODER::MODER5::Output::Set();
  GPIOC::MODER::MODER8::Output::Set();
  GPIOC::MODER::MODER9::Output::Set();

  for(;;)
  {
     GPIOA::ODR::ODR5::High::Set();
     delay(1000000);
     GPIOC::ODR::ODR5::High::Set();
     delay(1000000);
     GPIOC::ODR::ODR9::High::Set();
     delay(1000000);
     GPIOC::ODR::ODR8::High::Set();
     delay(1000000);
     GPIOA::ODR::ODR5::Low::Set();
     delay(1000000);
     GPIOC::ODR::ODR5::Low::Set();
     delay(1000000);
     GPIOC::ODR::ODR9::Low::Set();
     delay(1000000);
     GPIOC::ODR::ODR8::Low::Set();
     delay(1000000);
  }
  return 1;
}
----

=== 1.3. Совмещенный режим (5 секунд «елочка», 5 секунд «шахматка»)

Следующей задачей было объединение двух режимов с цикличным переключением. Задержки были подобраны таким образом, чтобы полный цикл одного режима занимал примерно 5 секунд.

[source, cpp]
----
int main(void)
{
  RCC::AHB1ENR::GPIOAEN::Enable::Set();
  RCC::AHB1ENR::GPIOCEN::Enable::Set();
  
  GPIOA::MODER::MODER5::Output::Set();
  GPIOC::MODER::MODER5::Output::Set();
  GPIOC::MODER::MODER8::Output::Set();
  GPIOC::MODER::MODER9::Output::Set();

  while (1)
  {
    // Режим "Елочка" (3 цикла для ~5 секунд)
    for (int count = 0; count < 3; ++count)
    {
      GPIOA::ODR::ODR5::High::Set();
      delay(1000000);
      GPIOC::ODR::ODR5::High::Set();
      delay(1000000);
      GPIOC::ODR::ODR9::High::Set();
      delay(1000000);
      GPIOC::ODR::ODR8::High::Set();
      delay(1000000);
      GPIOA::ODR::ODR5::Low::Set();
      delay(1000000);
      GPIOC::ODR::ODR5::Low::Set();
      delay(1000000);
      GPIOC::ODR::ODR9::Low::Set();
      delay(1000000);
      GPIOC::ODR::ODR8::Low::Set();
      delay(1000000);
    }

    // Режим "Шахматка" (2 цикла для ~5 секунд)
    for (int count = 0; count < 2; ++count)
    {
      GPIOA::ODR::ODR5::High::Set();
      GPIOC::ODR::ODR8::High::Set();
      delay(1000000);

      GPIOA::ODR::ODR5::Low::Set();
      GPIOC::ODR::ODR8::Low::Set();
      delay(1000000);

      GPIOC::ODR::ODR5::High::Set();
      GPIOC::ODR::ODR9::High::Set();
      delay(1000000);

      GPIOC::ODR::ODR5::Low::Set();
      GPIOC::ODR::ODR9::Low::Set();
      delay(1000000);
    }
  }
}
----

== Этап 2. Переход к объектно-ориентированному подходу

Код на этапе 1 имеет жесткую привязку к конкретным портам и пинам. При изменении количества светодиодов или используемых выводов приходится переписывать логику `main`. Для решения этой проблемы была разработана UML-диаграмма классов и начат рефакторинг.

В Workspace среды IAR были созданы две папки:
* **Contracts** — для хранения абстракций (интерфейсов).
* **Implementation** — для конкретных реализаций.

=== 2.1. Интерфейс IPin (`Contracts/IPin.h`)

Интерфейс абстрагирует работу с физическим выводом микроконтроллера.

[source, cpp]
----
#ifndef UNTITLED2_CONTRACTS_IPIN_H
#define UNTITLED2_CONTRACTS_IPIN_H

class IPin
{
  public:
    virtual ~IPin() = default;
    
    virtual void Set() = 0;
    virtual void Reset() = 0;
    virtual void Toggle() = 0;
    virtual bool GetState() const = 0;
};

#endif
----

=== 2.2. Шаблонный класс Pin (`Implementation/Pin.h`)

Класс `Pin` реализует интерфейс `IPin` с помощью шаблонов C++. Это позволяет передавать в качестве параметров конкретные регистры портов (`TPort`) и номер пина (`pinNum`), не дублируя код.

[source, cpp]
----
#ifndef UNTITLED2_IMPLEMENTATION_PIN_H
#define UNTITLED2_IMPLEMENTATION_PIN_H

#include <cassert>
#include "IPin.h"

template <typename TPort, int pinNum>
class Pin final : public IPin
{
  public:
    void Set() override
    {
      TPort::Set(uint8_t(1U) << pinNum);
    }
    
    void Reset() override
    {
      //TPort::Reset(uint8_t(1U) << pinNum);
    }
    
    void Toggle() override
    {
      TPort::Toggle(uint8_t(1U) << pinNum);
    }
    
    bool GetState() const override
    {
      // Пока не реализуем (используется для кнопок)
      assert(true);
    }
};

#endif
----

== Этап 3. Реализация управления светодиодами (Led и ILed)

Опираясь на UML-диаграмму, были разработаны интерфейсы и классы для работы со светодиодами. Класс светодиода агрегирует в себе интерфейс пина (`IPin&`), что позволяет легко менять физический пин без изменения логики самого светодиода.

=== 3.1. Интерфейс ILed (`Contracts/ILed.h`)

[source, cpp]
----
#ifndef UNTITLED2_CONTRACTS_ILED_H
#define UNTITLED2_CONTRACTS_ILED_H

class ILed
{
public:
    virtual void Light() = 0;
    virtual void PutOut() = 0;
    virtual void Toggle() = 0;

    virtual ~ILed() = default; 
};

#endif //UNTITLED2_CONTRACTS_ILED_H
----

=== 3.2. Класс Led (`Implementation/Led.h`)

[source, cpp]
----
#ifndef UNTITLED2_IMPLEMENTATION_LED_H
#define UNTITLED2_IMPLEMENTATION_LED_H

#include "ILed.h"
#include "IPin.h"

class Led final : public ILed
{
public:
    explicit Led(IPin& pin)
        : pin(pin)
    {
    }

    void Light() override
    {
        pin.Set();
    }

    void PutOut() override
    {
        pin.Reset();
    }

    void Toggle() override
    {
        pin.Toggle();
    }

private:
    IPin& pin;
};

#endif //UNTITLED2_IMPLEMENTATION_LED_H
----

== Заключение

В ходе выполнения работы были успешно решены следующие задачи:
1. Реализованы базовые алгоритмы управления светодиодами («елочка» и «шахматка») с использованием регистров микроконтроллера.
2. Объединены режимы с использованием временных задержек.
3. Проведен рефакторинг кода с переходом от процедурного стиля к объектно-ориентированному.
4. Разработана архитектура на основе UML-диаграммы, применены принципы SOLID (в частности, Dependency Inversion — зависимость от абстракций `IPin` и `ILed`, а не от конкретных реализаций).
5. Использованы шаблоны C++ (`template`) в классе `Pin`, что позволило избавиться от дублирования кода при работе с разными портами ввода-вывода.

Применение интерфейсов и шаблонов делает код масштабируемым. Теперь для добавления нового светодиода достаточно создать объект `Led` и передать в него экземпляр `Pin`, а логика работы с ними может быть вынесена в отдельный класс `Mode`, что позволяет легко менять количество элементов системы без переписывания низкоуровневого кода.
