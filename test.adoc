== 1. Инструментальная среда разработки

Для разработки программ под микроконтроллеры в рамках курса используется среда *IAR Embedded Workbench for Arm*. Компания IAR поставляет две версии продукта: *Evaluation* (полный функционал, но ограничение 30 дней) и *Kickstart* (без ограничения по времени, но с ограничением на размер генерируемого кода — 32 Кбайт). В работе применяется версия *IAR Embedded Workbench for Arm 9.10.2*.

IAR EW представляет собой классическую интегрированную среду разработки (IDE), которая объединяет в себе текстовый редактор, компилятор, компоновщик, отладчик и ряд вспомогательных инструментов. Это позволяет выполнять весь цикл разработки в одном окне, не переключаясь между сторонними утилитами.

== 2. Процесс создания исполняемого образа

Преобразование исходного кода в файл прошивки для микроконтроллера проходит два основных этапа: трансляцию и компоновку.

На этапе *трансляции* исходный код на языке C/C++ преобразуется в машинно-зависимый код. Важно различать понятия: 

* Трансляция — это общий процесс преобразования программы из одного языка в другой (или в машинный код), 
* Компилятор — это конкретный вид транслятора, который формирует объектный или машинный код из исходного текста. 

На выходе компилятора обычно получаются объектные файлы. Библиотеки же могут формироваться отдельно (например, путем упаковки или компоновки объектных файлов) для повторного использования в других проектах.

На этапе *компоновки* линковщик объединяет объектные файлы и библиотеки в единый исполняемый файл формата ELF. При этом конфигурационный файл `.icf` не добавляется в ELF как входной модуль, а используется линковщиком для настройки размещения кода и данных в адресном пространстве микроконтроллера. Полученный ELF-файл затем либо загружается в микроконтроллер через программатор, либо подаётся на вход отладчику.

== 3. Запуск и отладка программы

Заключительным этапом разработки является отладка. Процесс разработки ПО носит итеративный характер (Design → Develop → Debug). Отладка необходима для поиска и устранения логических и алгоритмических ошибок, которые не выявил компилятор. Для этого применяются точки останова (breakpoints), позволяющие приостановить выполнение программы в заданном месте и проанализировать текущее состояние регистров и памяти.

Компоновщик IAR формирует ELF-файл, содержащий исполняемый образ программы. Этот файл можно использовать двумя способами: загрузить в отладчик (IAR C-SPY или сторонний, например GDB) либо записать в ПЗУ микроконтроллера через программатор.

Функция `int main()` является точкой входа пользовательской C++-программы. Однако она не является самой первой инструкцией, выполняемой микроконтроллером после сброса. До вызова `main()` выполняется startup-код, который осуществляет ряд служебных действий:

* *инициализация стека* — сразу после подачи питания указатель стека (MSP) получает значение из первого слова таблицы векторов, а счётчик команд (PC) — адрес обработчика сброса из второго слова;
* *обнуление переменных с нулевой инициализацией* — в памяти заполняются нулями глобальные и статические объекты, которые не были явно инициализированы (например, `int i;` на глобальном уровне). Локальные автоматические переменные при этом не обнуляются;
* *инициализация инициализированных переменных* — на этапе startup начальные образы глобальных и статических данных (например, `int i = 6;`) копируются из ПЗУ в ОЗУ;
* *вызов `main()`* — только после всех этих действий управление передаётся пользовательской функции.

Кроме того, если в проекте используются прерывания, необходимо корректно заполнить соответствующие векторы в таблице прерываний. Если обработчик не задан, поведение будет определяться значением вектора по умолчанию: часто там установлена заглушка (default handler), которая может привести к зацикливанию или сбою программы.

== 4. Преимущества IAR Embedded Workbench

За последние годы IAR EW заметно продвинулась как в удобстве использования, так и в поддержке современных стандартов языка. Начиная с версии 8.40 среда поддерживает стандарт C++17, что важно для написания надёжного и читаемого кода даже в небольших встраиваемых проектах.

Среди ключевых возможностей среды можно выделить:

* поддержка языков C и C++;
* наличие оптимизации кода;
* частичная поддержка многопоточности — без `condition_variable`, `future`, `mutex`, `shared_mutex` и `thread`, при этом `atomic` реализован только для типов, которые поддерживаются аппаратно;
* встроенный контроль размера стека;
* поддержка RTOS;
* статический анализ кода с наборами правил MISRA C++:2008, SECURITY, CERT и STDCHECKS;
* динамический анализ кода при помощи инструмента C-RUN;
* сертификация по стандартам безопасности IEC 61508 и ISO 26262 (сертификат SIL3, выданный TÜV SÜD);
* полная поддержка микроконтроллера STM32F411RE.

  // Switch on external 16 MHz oscillator

  while (RCC::CR::HSIRDY::NotReady::IsSet())

{
  for(int i = 0; i < cycles; ++i)

  }

int main()
{

== 6. Вопросы по разделу

=== Дайте определение понятию «интегрированная среда разработки»
*Ответ:* Интегрированная среда разработки (IDE) — это комплекс программных средств, объединяющий в себе текстовый редактор, компилятор, компоновщик, отладчик и другие вспомогательные инструменты. Это позволяет разработчику выполнять весь цикл создания программы (написание кода, сборка, отладка) в рамках одного приложения.

=== Что такое компилятор и чем он отличается от транслятора?
*Ответ:* Транслятор — это общее понятие для любой программы, которая переводит исходный код с одного языка программирования на другой. Компилятор — это частный случай транслятора, который переводит исходный код на языке высокого уровня (например, C/C++) в машинный код или объектные файлы, понятные процессору.

=== Что такое компоновщик и какие функции он выполняет?
*Ответ:* Компоновщик (линковщик) — это программа, которая объединяет объектные файлы и библиотеки в единый исполняемый файл (ELF). Его функции включают разрешение внешних ссылок (связывание вызовов функций с их определениями), а также распределение кода и данных по адресам памяти в соответствии с конфигурационным файлом (`.icf`).

=== Почему важен процесс проектирования ПО и какие задачи входят в этот процесс? Дорисуйте процесс разработки ПО, описанный на изображении, с учётом итеративности связей.
*Ответ:* Проектирование важно, потому что позволяет выявить архитектурные ошибки на ранних этапах, когда их исправление стоит дешевле всего. В задачи проектирования входит анализ требований, выбор архитектуры, разработка алгоритмов и интерфейсов. Процесс разработки носит итеративный характер: цикл *Проектирование → Разработка → Отладка*. Если на этапе отладки выявляются ошибки проектирования или архитектуры, процесс возвращается на предыдущие этапы, образуя замкнутый цикл.

=== Зачем нужна отладка и в каких случаях она применяется? Для чего применяются точки останова?
*Ответ:* Отладка нужна для поиска и устранения логических и алгоритмических ошибок, которые компилятор не может обнаружить (так как код синтаксически верен, но работает не так, как задумано). Она применяется при тестировании программы. Точки останова (breakpoints) используются для принудительной приостановки выполнения программы в конкретной строке кода, чтобы разработчик мог изучить текущие значения переменных, регистров и состояние памяти в этот момент.

=== Какие ещё важные характеристики IAR Workbench можно добавить в таблицу?
*Ответ:* В таблицу можно добавить следующие важные характеристики:

* Наличие статического анализатора кода *C-STAT* (работает по правилам MISRA C/C++).
* Интеграция с популярными системами контроля версий (Git, SVN, Mercurial).
* Поддержка многопроцессорных (multi-core) систем и гетерогенных архитектур.
* Возможность тонкой настройки уровней оптимизации по размеру кода или по скорости выполнения.
