== Введение

Данный отчет составлен по материалам лекции №1 «Среда разработки программ для микроконтроллера». 

== 1. Инструментальная среда разработки

Для разработки программ под микроконтроллеры в рамках курса используется среда IAR Embedded Workbench for Arm. Компания IAR поставляет две версии продукта: 

* Evaluation (полный функционал, но ограничение 30 дней) 

* Kickstart (без ограничения по времени, но с ограничением на размер генерируемого кода — 32 Кбайт). 

В работе применяется версия IAR Embedded Workbench for Arm 9.50.2.

IAR EW представляет собой классическую интегрированную среду разработки, которая объединяет в себе текстовый редактор, компилятор, компоновщик, отладчик и ряд вспомогательных инструментов. Это позволяет выполнять весь цикл разработки в одном окне, не переключаясь между сторонними утилитами.

== 2. Процесс создания исполняемого образа

Преобразование исходного кода в файл прошивки для микроконтроллера проходит два основных этапа: трансляцию и компоновку.

На этапе трансляции компилятор переводит исходный код на языке C/C++ в объектные файлы и библиотеки. Эти файлы ещё не являются готовой программой, но могут повторно использоваться в других проектах.

На этапе компоновки линковщик собирает объектные файлы, внешние и стандартные библиотеки, а также конфигурационный файл `.icf` в единый исполняемый файл формата ELF. Именно этот файл затем либо загружается в микроконтроллер через программатор, либо подаётся на вход отладчику.

== 3. Запуск и отладка программы

Заключительным этапом разработки является отладка. Компоновщик IAR формирует ELF-файл, содержащий исполняемый образ программы. Этот файл можно использовать двумя способами: загрузить в отладчик (IAR C-SPY или сторонний, например GDB) либо записать в ПЗУ микроконтроллера через программатор.

Отдельно стоит отметить, что функция `int main()` только кажется точкой входа. С точки зрения пользователя программа действительно начинается с неё, однако микроконтроллер перед этим выполняет ряд служебных действий:

* *инициализация стека* — сразу после подачи питания указатель стека (MSP) получает значение из первого слова таблицы векторов, а счётчик команд (PC) — адрес обработчика сброса из второго слова;
* *обнуление неинициализированных переменных* — данные, объявленные без начального значения (например, `int i;`), размещаются в памяти и заполняются нулями;
* *инициализация инициализированных переменных* — значения переменных вида `int i = 6;` копируются из ПЗУ в ОЗУ;
* *вызов `main()`* — только после всех этих действий управление передаётся пользовательской функции.

Кроме того, если в проекте используются прерывания, в таблицу векторов необходимо заранее добавить адреса соответствующих обработчиков. Без этого прерывание приведёт к переходу по неверному адресу и, скорее всего, к зависанию программы.


== 4. Лабораторная работа

=== 4.1. Цель работы

Изучить процесс создания проекта в IAR Embedded Workbench, настройки компоновщика и запуска программы на микроконтроллере STM32F411RE.

=== 4.2. Ход выполнения

В ходе лабораторной работы были выполнены следующие шаги: создание нового проекта, выбор целевого микроконтроллера STM32F411RE, добавление необходимых файлов драйверов и файла запуска, настройка параметров компоновщика, компиляция и запуск программы в режиме отладки.

=== 4.3. Код лабораторной работы (файл main.cpp)

[source,cpp]
----
#include "rccregisters.hpp"   // for RCC
#include "gpioaregisters.hpp" // for GPIOA
#include "gpiocregisters.hpp" // for GPIOC

std::uint32_t SystemCoreClock = 16'000'000U;

extern "C" int __low_level_init(void)
{
  // Switch on external 16 MHz oscillator
  RCC::CR::HSION::On::Set();
  while (RCC::CR::HSIRDY::NotReady::IsSet())
  {

  }
  // Switch system clock on external oscillator
  RCC::CFGR::SW::Hsi::Set();
  while (!RCC::CFGR::SWS::Hsi::IsSet())
  {

  }
  
  RCC::APB2ENR::SYSCFGEN::Enable::Set();

  return 1;
}

void delay(int cycles)
{
  for(int i = 0; i < cycles; ++i)    
  {   
    asm volatile("");
  }    
}

int main()
{  
  // Подать тактирование на порт A
  RCC::AHB1ENR::GPIOAEN::Enable::Set();
  // Подать тактирование на порт C
  RCC::AHB1ENR::GPIOCEN::Enable::Set();
  // Порт A.5 на вывод
  GPIOA::MODER::MODER5::Output::Set();
  // Порта C.5, C.8, C.9 на вывод
  GPIOC::MODER::MODER5::Output::Set();
  GPIOC::MODER::MODER8::Output::Set();
  GPIOC::MODER::MODER9::Output::Set();
  
  for(;;)
  {
     GPIOA::ODR::ODR5::High::Set();
     delay(1000000);
     GPIOC::ODR::ODR5::High::Set();
     delay(1000000); 
     GPIOC::ODR::ODR9::High::Set();
     delay(1000000);
     GPIOC::ODR::ODR8::High::Set();
     delay(1000000); 
     GPIOA::ODR::ODR5::Low::Set();
     delay(1000000);
     GPIOC::ODR::ODR5::Low::Set();
     delay(1000000);
     GPIOC::ODR::ODR9::Low::Set();
     delay(1000000);
     GPIOC::ODR::ODR8::Low::Set();
     delay(1000000);
  }
  
  return 1;
}
----

=== 4.4. Результаты

Компиляция проекта прошла успешно, ошибок не обнаружено. Программа была загружена в микроконтроллер STM32F411RE с помощью отладчика ST-Link. В ходе выполнения программы наблюдается последовательное мигание светодиодов, подключенных к выводам PA5, PC5, PC8 и PC9.

=== 4.5. Выводы

В ходе лабораторной работы были изучены основные этапы создания проекта в IAR Embedded Workbench for Arm, настройка параметров компилятора и компоновщика, а также процесс сборки и загрузки программы в микроконтроллер. Получены практические навыки работы с регистрами периферии (RCC, GPIO) для управления светодиодами.
